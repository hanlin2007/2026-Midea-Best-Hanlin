# 代码库结构解读（重构后的最终系统）

本文档只描述**重构后的最终系统**：仓库现已合并为单一系统包 `src/szy/`
（目标说话人语音指令识别管线）与内核层 `src/midea_qiji/`（baseline 内核与
全仓库公共部件）。历史阶段包已全部删除，阶段演进历史（v1→v2→v4 的设计决策
与实验数字）请看 `docs/CURRENT_BEST_PIPELINE_SZY_V1.md` / `_V2.md` /
`_V3_EXPERIMENTAL.md` / `_V4.md` 与 `docs/SZY_V1.md`。

一句话总览：这是一条**目标说话人语音识别**竞赛管线——唤醒音频定位目标人 →
融合门控判定指令音频是否含目标人 →（接受时）dasynth 微调的 MossFormer2 盲
分离两路 → FireRed ASR 转写 → 音色触发规则决定用原始转写还是分离通道转写，
任何异常回退原始转写。

配套阅读：本文档第 4 节做纯文本总览走读；一条样本从读入到提交物落盘的逐段
细节请看三条流动全景文档：

- `docs/一条数据的流动全景-01-样本加载与分离前端.md`
- `docs/一条数据的流动全景-02-识别与门控决策.md`
- `docs/一条数据的流动全景-03-汇总与提交产出.md`

### 1.2 分层架构（依赖只能向下）

```
入口层     scripts/（run.sh 及各工具脚本）、tests/
                 │  调用 python -m szy.cli / szy.train / ... 或 import
                 ▼
系统层     src/szy/        生产管线：配置、融合门控、torch 分离器、
                           微调训练、诊断、共享工具、汇总写出
                 │
                 ▼
内核层     src/midea_qiji/ baseline 内核与全仓库公共部件：文本口径、
                           音频读取、模型路径解析、声纹 embedding 与门控、
                           冻结决策规则、ASR 后端、baseline CLI
                 │
                 ▼
vendor     third_party/mossformer2/   外部模型定义（ClearerVoice-Studio）
资产层     model/  dataset/  outputs/（不进 git）
```

规则：**只允许向下依赖**（scripts/tests → szy → midea_qiji → third_party）。
`src/szy/` 可以 import `midea_qiji`，反向不行；工具脚本不得挖掘任何包的私有函数。

### 2.3 `scripts/`（10 个）

| 脚本 | 用法 | 用途 |
|---|---|---|
| `run.sh` | `bash scripts/run.sh [--limit N]` | **现役生产入口**：配好 PYTHONPATH/MODELSCOPE_CACHE 等环境变量后跑 `python -m szy.cli` 全量（§3.1） |
| `ablate_pretrained.sh` | `bash` | 消融编排：等 GPU 上训练结束后，用 ClearerVoice 预训练分离器（零 dasynth 微调）跑 DatasetA 全量，分解"模型容量 vs 微调"的收益 |
| `sweep_epoch_eval.sh` | `bash` | 训练过程中逐 2 epoch 存档扫描：三张评估 GPU 各负责一组 epoch，每出现一个快照就跑一次 DatasetA 全量 |
| `sweep_gpu1_rest.sh` | `bash` | GPU1 补跑器：等预训练消融结束后再评估指定 epoch（ep10/ep16） |
| `sweep_sv_epochs.sh` | `bash` | SV 重训逐 2 epoch 评估 watcher：快照一出现就做"重训 logistic → valid 定阈 → 全链路重放"，结果追加 jsonl |
| `check_models.py` | `python scripts/check_models.py` | 资产自检：按 `model/MANIFEST.json` 校验存在性/软链/字节数/sha256，并扫描工作区残留权重（哈希等口径与 relocate 共用同一实现） |
| `relocate_workspace_models.py` | `python` | 一次性资产搬迁工具：把工作区模型搬进 `model/` 留兼容软链，生成 `model/MANIFEST.json` |
| `build_replay_assets.py` | `PYTHONPATH=src python scripts/build_replay_assets.py --part dataseta\|valid` | 一次性：为离线重放补 FireRed 转写文本资产（被拒样本的 raw/分离通道文本等） |
| `replay_full.py` | `PYTHONPATH=src python scripts/replay_full.py --mode validate\|eval [--ft-ckpt ...]` | 离线全链路重放：给定 ft SV checkpoint 重放整条决策链（validate 逐位复现 0.8679 校验重放器；eval 评估重训 SV 快照），不重跑 ASR/分离 |
| `replay_gate_ablation.py` | `python scripts/replay_gate_ablation.py --detail ... --fusion ...` | 零 GPU 门控消融：基于 detail.json 的 6 维门控特征重放任意门控变体（融合 vs 单前端 vs 单维），含外部阈值口径与 oracle 上限扫描 |

全部脚本自包含 `sys.path` 注入（或由 run.sh 设 PYTHONPATH），只依赖 `szy` 与

## 3. 入口与调用关系

### 3.1 现役入口：`bash scripts/run.sh`

推荐方式（已配好所有环境变量），追加参数直接透传给 `szy.cli`（如
`bash scripts/run.sh --limit 5`）。完整等价命令：

```bash
cd <仓库根目录>
CUDA_VISIBLE_DEVICES=1 \
PYTHONPATH=src:model/runtime/vendor \
MODELSCOPE_CACHE=model/workspace/midea/models/modelscope \
HF_HUB_OFFLINE=1 \
python -u -m szy.cli \
  --data-root dataset/dataset_test/datasetA/datasetA \
  --jsonl dataset/dataset_test/datasetA/datasetA/pos.jsonl \
          dataset/dataset_test/datasetA/datasetA/neg.jsonl \
  --config configs/pipeline_firered.json \
  --output outputs/submission.json \
  --final-output outputs/detail.json \
  --checkpoint-output outputs/checkpoint.json \
  --manifest-output outputs/manifest.json
```

可用 `PYTHON_BIN`、`CUDA_VISIBLE_DEVICES`、`MODELSCOPE_CACHE`、`HF_HUB_OFFLINE`
环境变量覆盖运行环境。

## 4. pipeline_plaintext：管线的纯文本走读

本节用纯文字走读 `szy.cli.main()` 与 `SzyRunner.process()` 的执行逻辑。
每一段回答"这一步做什么、为什么这么做"。逐段细节（每条路径的字段口径、
缓存命名、阈值含义）请看三条流动全景文档（01 样本加载与分离前端 / 02 识别
与门控决策 / 03 汇总与提交产出），本节只做总览。

**① 配置加载与校验。** CLI 先把 JSON 读成 `SzyConfig`。这个 dataclass 被
`frozen=True` 冻结——配置一次加载后不可变，防止运行中途被误改。JSON 里出现
任何配置类没有的键都会**立即报错**，而不是静默忽略。为什么：拼错的配置项
（比如把 `moss_model` 写成 `moss_models`）如果被默默吞掉，系统会用默认值
静默跑出另一条结果，事后才发现等于白跑；报错让这类错误在启动时就暴露。
之后 `--model-root` 会以覆盖方式重建配置实例。

**② 样本读取。** `read_many_jsonl` 按顺序拼接所有清单（pos + neg），逐行
解析大赛官方字段（唤醒音频/识别音频/识别文本/唤醒文本），把相对路径按
`--data-root` 拼成绝对路径，装入 `Sample`。`--limit` 截断用于冒烟。为什么
用官方字段与相对路径：数据根目录可变（用户机器路径不同），清单保持原样，
只有根目录一个变量。

**③ 断点续跑。** `--resume` 时读回 checkpoint 里已完成样本的 id 集合，
按与本次相同的 id 口径（`submission_id` + `id_mode`）过滤掉它们，并继承
已耗时长。为什么逐条落盘 checkpoint：全量约 26~46 分钟，任何中断都不必
从头再来；id 用同一口径生成是续跑正确的前提。

**④ 逐样本循环。** 每条样本交给 `SzyRunner.process`，返回一串可 JSON
序列化的字段（detail.json 的一行）。结果先带默认值（拒绝态），再逐步覆盖；
这样任何一步提前返回，行结构都完整、汇总不炸。为什么"先写默认再覆盖"：
生产系统里每一行都必须有完整 schema，宁可先填保守值。

**⑤ 分离缓存。** 先算唤醒/指令各两路分离输出的缓存路径
（`{item_id}_wake_ms{0,1}.wav` / `{item_id}_command_ms{0,1}.wav`），
两个文件都已存在就**直接复用**，否则跑分离器：严格 16k 单声道读取 →
整波推理 → 峰值归一化到 ±0.5 → PCM_16 落盘。为什么：分离是全链路最贵的
一步，缓存让断点续跑、消融重跑、重放全部免费复用；峰值归一化与历史 ONNX
口径一致，防止爆音且保证下游可比。

**⑥ FireRed 转写。** 4 个分离通道一次性批量转写，返回归一化文本 + 置信度
（非法/非有限置信度回退 1.0）。转写时静默模型打印噪音，用调用前缀区分日志
来源。为什么先转写分离通道：唤醒锚点和门控特征都依赖分离通道的文本；批量
调用比分四次省调度开销；文本统一走 `midea_qiji.text` 归一化，保证后面编辑
距离比较的口径一致。

**⑦ 唤醒锚点。** `select_wake_anchor` 在两路分离唤醒转写里选"真正说出唤醒词"
的那一路：两路都有文本时按编辑距离选更接近官方唤醒文本的；某一路转写为空
（分离失败）时回退用**原始唤醒音频**当锚点。为什么：锚点就是门控的注册
样本，注册进错了人，后面全错；分离器偶尔会毁掉一路，此时原始唤醒比坏掉的
分离通道更可信。曾验证"非空通道直选"在 CER 上更优，但官方公式分
(1−CER+RR)/2 里 RR 权重高，raw 回退版总分更高，故保持回退规则。

**⑧ 融合门控打分。** 两个 ERes2NetV2 前端（官方预训练 + 分离域微调，同一
基座只换 encoder 权重）对五段波形各提 embedding，算 6 维余弦特征
（pre_raw / ft_raw / pre_sep / ft_sep / ch_sim_pre / ch_sim_ft），z-score
标准化后线性融合出分。为什么双前端：预训练模型泛化好、微调模型适应分离域，
融合比任一单独更稳；一次打分同时产出三样东西——接受判定、融合分、全部
逐通道余弦——下游候选选择与音色触发**复用同一批 embedding，不再重复推理**。
如果指令两分离通道转写为空，原始指令也会作为候选参与"分离收益"特征，避免
空通道污染门控输入。

**⑨ 接受 / 拒绝。** 融合分 ≥ −0.6469 判接受。拒绝时 content 置空、
route=fusion_reject，样本直接结束。为什么阈值是这个数：在 dasynth valid
上标定，零 DatasetA 调参；门控消融显示该阈值已坐在 DatasetA oracle 上限上，
调优空间为零。拒绝样本对负样本贡献 RR，对正样本扣 PR——门控是 PR/RR 的
总闸门。

**⑩ 音色触发。** 接受后转写原始指令，算两个文本特征（字速 + 指令关键词
命中数），并算 `sv_diff` = 分离通道里目标嗓音余弦的最大值 − 原始混合里
目标嗓音的余弦（复用门控已算的余弦）。`should_switch_command_timbre` 用
（置信度, 关键词, sv_diff）三特征判定是否切换。为什么 sv_diff 是主判决：
它直接测量"分离是否让目标嗓音比原始混合更突出"——这正是切换本身的物理
机制；置信度管必坏线（极低置信必切），关键词管高置信否决（自信转写但不像
指令 + 音色说分离更好 = 大概率转错了人）。该规则冻结，改动即破坏复现。

**⑪ 候选选择。** 触发切换后：若分离通道文本为空则回退原始转写；否则用
微调前端对两分离通道的余弦（门控时已算好）直接选更大者（ms0/ms1）作为
最终转写。为什么：与门控同一打分原理，逻辑一致，且**零额外 embedding
计算**；实测与历史 eres+cam 差分打法打平，还避开了对比通道污染。

**⑫ 异常兜底。** 任何一步抛异常都不让样本"消失"：先重试原始指令转写
（route=raw_fallback_error），连这也失败就 content 置空
（route=empty_fallback_error），并把异常类型写入 error 字段。为什么：
竞赛提交必须覆盖每条样本；生产系统宁可给保守答案也不丢样本，且 error
字段让坏样本事后可查、可修。

**⑬ 汇总。** `summarize` 按 label 分正负：正样本算归一化编辑距离口径的
CER 与 PR，负样本算 RR，并统计路由分布、切换次数、分离错误数。为什么
按归一化口径：与官方评测一致，任何一处不归一化都会系统性偏差。

**⑭ 三件套写出。** `write_outputs` 写 submission.json（竞赛格式：
result.results + avg_cer/avg_rr/duration）与 detail.json（summary + 全字段
逐样本明细，含 6 维门控特征，供消融重放）；`main` 再写 manifest.json
（本次运行的完整配置 + 分离器/融合包/声纹权重的 sha256 指纹）。为什么
manifest：哪份配置 + 哪份权重跑出的结果可追溯，出争议时能证明复现条件。

## 5. 命名与导入规范（请后续遵守）

1. **依赖单向向下**：scripts/tests → szy → midea_qiji → third_party。
   禁止低层 import 高层；工具脚本只准用公共 API，不得挖私有函数。
2. **跨模块复用的函数不加下划线前缀**；仅模块内私有的才用 `_`。
3. **重型依赖延迟导入**（torch / modelscope / FireRed / peft / wandb），
   保证轻量模块可被 import；`szy.separator` 在 `SzyRunner` 构造时才导入
   （其 import 会污染 sys.path 并引入 torch），因此 `--help` 与单测在无
   torch 环境也能跑。
4. **从 canonical 位置导入**：文本工具 `midea_qiji.text`、音频
   `midea_qiji.audio`、模型解析 `midea_qiji.paths`、共享工具
   `szy.helpers`、指标 `szy.metrics`；`midea_qiji.infer` / `gate` 的
   re-export 仅为兼容历史代码与文档。
5. **冻结语义不得改动**：`normalize_transcript` 归一化口径、`moss_candidate`
   决策规则与阈值、`SzyConfig` 默认值、`gate_fusion.json` 特征顺序（必须与
   `FUSION_FEATURE_KEYS` 一致，顺序不符会直接报错）。改动前先跑 `tests/`，
   再对照 `docs/CURRENT_BEST_PIPELINE_SZY_V4.md` 的基线数字（0.8679）。

## 6. 注意事项

- **torch 必须 CUDA 版**：`requirements.txt` 已配置 cu128 轮子源；纯 CPU
  torch 无法跑分离器/声纹前端的 GPU 推理。其余核心依赖：modelscope、
  numpy、soundfile、tqdm、qwen-asr（baseline 路线）。
- **`model/` 与 `dataset/` 不进 git**（.gitignore 排除），需按
  `model/README.md` 填充；`outputs/`（分离缓存、checkpoint、提交物）同样
  不进 git，可随时重新生成。
- **`check_models.py` 依赖 `model/MANIFEST.json`**：该文件由
  `relocate_workspace_models.py` 在用户机器执行搬迁后生成，不在仓库内；
  未搬迁前 check_models 不可用。
- **kaldi_native_fbank 为 vendored py3.10 编译版**：位于
  `model/runtime/vendor/`，无需 pip 安装，但 PYTHONPATH 必须包含该目录
  （`run.sh` 已处理）。
- **`third_party/mossformer2/` 是外部 vendor 代码**（ClearerVoice-Studio），
  仅改了包内相对导入；配套官方预训练权重约 670MB 需自行从 ModelScope 下载。
- 生产全量运行约 26~46 分钟；checkpoint 逐样本落盘，中断后加 `--resume`
  续跑即可。

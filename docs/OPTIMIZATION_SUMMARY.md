## 1. 拼音音素匹配

### 问题
当 ASR 产生同音字时，字符级编辑距离会失败：
- 参考文本: "你好科慕" 
- ASR 输出: "你好科目" (拼音相同，字不同)
- 编辑距离: 1 (错误惩罚)

### 解决方案
将文本转换为拼音音节，在语音空间计算相似度：

```python
def phoneme_similarity(text_a: str, text_b: str) -> float:
    py_a = _to_pinyin_str(text_a)  # "你好科慕" → "nihaokemu"
    py_b = _to_pinyin_str(text_b)  # "你好科目" → "nihaokemu"
    
    if py_a == py_b:
        return 0.0  # 完美匹配
    
    dist = levenshtein_distance(py_a, py_b)
    return -dist  # 返回负距离（越大越好）
```

### 实现
- **文件**: `src/phoneme.py`
- **库**: pypinyin 用于中文 → 拼音转换
- **模式**: TONE3 (带声调数字)，然后去除数字

### 性能影响
- **CER**: 0.1945 → 0.1831 (-0.0114)
- **RR**: 0.9304 → 0.9283 (-0.0021)
- **PR**: 0.9150 → 0.9164 (+0.0014)
- **Score**: 0.8679 → 0.8726 (+0.0047)

### 为什么有效
- 同音字映射到相同的拼音 → 距离 = 0
- 语音相似但不同的词 → 小距离
- 完全不同的词 → 大距离
- 与实际语义相似度有更好的相关性

### 权衡
- **平局处理**: 当两个源的拼音相似度相同时，回退到原始唤醒音频
- **覆盖范围**: 只帮助语音错误，不帮助语义错误

## 2. 唤醒词别名表

### 问题
同一唤醒词的不同表示：
- 英文: "hicolmo", "hi colmo", "hi-colmo"
- 中文: "你好科慕", "嗨科慕", "嗨口沫"
- ASR 可能输出这些变体中的任何一个

### 解决方案
双向别名表，将唤醒词扩展到所有已知变体：

```python
WAKE_WORD_ALIASES = {
    "hicolmo": ["haikemu"],      # 英文 → 中文拼音
    "haikemu": ["hicolmo"],      # 中文拼音 → 英文
    # 根据需要添加更多别名
}

def phoneme_similarity(text_a: str, text_b: str) -> float:
    # 将 text_b 扩展到所有别名
    aliases = [text_b] + WAKE_WORD_ALIASES.get(text_b, [])
    
    # 返回所有别名中的最佳匹配
    return max(phoneme_similarity_raw(text_a, alias) for alias in aliases)
```

### 实现
- **文件**: `src/phoneme.py`
- **结构**: 带双向映射的字典
- **匹配**: 计算所有别名的相似度，取最大值

### 性能影响
- **CER**: 无直接影响（唤醒锚点选择）
- **RR**: 无直接影响
- **PR**: 无直接影响
- **间接收益**: 更准确的唤醒锚点选择 → 更好的下游性能

### 为什么有效
- 处理唤醒词的 ASR 变体
- 双向: 对英文和中文唤醒词都有效
- 可扩展: 易于添加新别名

### 权衡
- **维护**: 需要手动更新别名表
- **覆盖范围**: 只帮助已知的唤醒词变体
- **风险**: 太多别名可能导致误匹配

## 3. N-best 重排序

### 问题
Beam search 产生多个假设，但 beam=1 只返回最佳的一个：
- 可能错过概率接近的更好替代方案
- 保守的 MBR (最小贝叶斯风险) 可以选择更好的假设

### 解决方案
启用带 N-best 输出的 beam search 并应用 MBR 重排序：

```python

firered_nbest_mode: "conservative_mbr"

# 重排序逻辑

    # 为每个假设计算 MBR 分数
    # 选择期望风险最小的假设
    # 只有当风险降低 > 阈值时才切换
```

### 实现
- **文件**: `src/szy_v2.py`
- **方法**: `_transcribe_with_nbest()`
- **阈值**: 切换假设的最小风险降低

### 性能影响
- **CER**: 0.1831 → 0.1822 (-0.0009)
- **RR**: 0.9283 → 0.9304 (+0.0021)
- **PR**: 0.9164 → 0.9142 (-0.0022)
- **Score**: 0.8726 → 0.8741 (+0.0015)

### 为什么有效
- 探索更多假设空间
- MBR 选择期望误差最小的假设
- 保守阈值防止有害的切换

### 权衡
- **计算**: 慢 3 倍 (beam_size=3)
- **覆盖范围**: 只应用于 1.3% 的样本
- **影响有限**: 大多数样本已经有很好的 top-1 假设

## 4. ELM (外部语言模型) 集成

### 问题
ASR 模型针对通用语音优化，而非领域特定命令：
- 可能偏好常见短语而非正确的技术术语
- 不知道设备名称、模式等

### 解决方案
集成外部语言模型，使 ASR 偏向领域特定词汇：

```python
# 配置
firered_elm_dir: "/home/hustdun/zhy_workspace/midea/outputs/szy_v4_beam3_elm/elm/model"
firered_elm_weight: 0.15

# 在 FireRedRecognizer 中集成
elm_score = language_model.score(hypothesis)
final_score = asr_score + elm_weight * elm_score
```

### 实现
- **文件**: `src/infer.py`
- **模型**: 来自 zhy workspace 的预训练 ELM
- **权重**: 0.15 (调优以达到平衡)

### 性能影响
- **CER**: 0.1822 → 0.1524 (-0.0298)
- **RR**: 0.9304 → 0.9177 (-0.0127)
- **PR**: 0.9142 → 0.9135 (-0.0007)
- **Score**: 0.8741 → 0.8867 (+0.0126)

**最大的单项提升！**

### 为什么有效
- 使 ASR 偏向领域特定词汇
- 纠正同音字错误 (例如 "调到" vs "掉到")
- 改善技术术语识别

### 权衡
- **RR 下降**: ELM 使 ASR 对假阳性更有信心
- **计算**: 额外的语言模型推理
- **依赖**: 需要预训练的 ELM 模型

## 5. 唤醒/命令通道分离

### 问题
对唤醒和命令通道使用相同的 ASR 配置会导致问题：
- 唤醒通道需要稳定的锚点选择 (beam=1)
- 命令通道受益于探索 (beam=3 + ELM)

### 解决方案
将 ASR 拆分为两个具有不同配置的实例：

```python
# 唤醒通道: 稳定、保守
self.wake_asr = FireRedRecognizer(
    beam_size=1,
    nbest=1,
    elm_dir=None,
    elm_weight=0.0
)

# 命令通道: 探索性、领域感知
self.asr = FireRedRecognizer(
    beam_size=3,
    nbest=3,
    elm_dir=config.firered_elm_dir,
    elm_weight=config.firered_elm_weight
)
```

### 实现
- **文件**: `src/szy_v2.py`
- **方法**: `_transcribe_wake()`, `_transcribe()`
- **路由**: 唤醒通道使用 `wake_asr`，命令通道使用 `asr`

### 性能影响
- **CER**: 0.1524 → 0.1438 (-0.0086)
- **RR**: 0.9177 → 0.9304 (+0.0127)
- **PR**: 0.9135 → 0.9150 (+0.0015)
- **Score**: 0.8867 → 0.8933 (+0.0066)

**恢复了 ELM 损失的 RR！**

### 为什么有效
- 唤醒锚点选择需要一致性 → beam=1 提供稳定性
- 命令转录需要准确性 → beam=3 + ELM 提供质量
- 关注点分离防止干扰

### 权衡
- **内存**: 两个 ASR 模型实例 (2x 内存)
- **复杂度**: 更多代码来管理两个实例
- **延迟**: 由于分离推理略慢

## 6. 条件阈值（已测试，未采用）

### 假设
使用多个信号做出更细致的接受/拒绝决策：
- 路由 (raw vs moss_candidate)
- 原始置信度
- N-best 应用
- 关键词分数
- 内容长度

### 方法
基于信号计算调整后的分数：

```python
adjusted_score = sv_score
if route == 'raw':
    adjusted_score += 0.3
if nbest_applied:
    adjusted_score += 0.5
if raw_confidence >= 0.9:
    adjusted_score += 0.2
if raw_confidence < 0.5:
    adjusted_score -= 0.3
if keyword_score < 1.0:
    adjusted_score -= 0.1
```

### 测试结果
- **拒绝 15 个样本**
- **12 个真阳性被错误拒绝** ❌
- **3 个假阳性被正确拒绝** ✓
- **精确率: 0.200** (非常差)

### 为什么失败
- 合法命令具有多样化的特征
- 低置信度不意味着假阳性
- 关键词分数不可靠 (许多有效命令有 0 个关键词)
- 信号太弱，无法区分假阳性

### 被错误拒绝的命令示例
```
❌ "关机空调" (CER=0.0, confidence=0.56, keywords=0)
❌ "关闭显示屏" (CER=0.0, confidence=0.35, keywords=0)
❌ "把风速调到最大" (CER=0.0, confidence=0.27, keywords=0)
```

### 结论
**未采用** - 该方法弊大于利。

## 关键洞察

### 什么有效
1. **语音相似度** > 字符相似度用于唤醒词匹配
2. **领域特定语言模型** 提供最大收益
3. **关注点分离** (唤醒 vs 命令) 防止干扰
4. **保守阈值** 防止有害变化

### 什么无效
1. 基于弱信号的**条件阈值**
2. 拒绝合法命令的**激进过滤**
3. **单信号决策** (需要多个强信号)

### 性能瓶颈
1. **假阳性**: 33 个样本被接受但应该被拒绝
2. **高置信度假阳性**: 27.3% 的 SV 分数 > 2.0
3. **CER-RR 权衡**: 改善一个通常会损害另一个

## 结论

优化之旅通过以下方式实现了 **2.9% 的分数提升** (0.8679 → 0.8933)：

1. **拼音音素匹配** (+0.0047): 更好的唤醒词锚点选择
2. **N-best 重排序** (+0.0015): 探索假设空间
3. **ELM 集成** (+0.0126): 领域特定语言偏向 (最大收益)
4. **唤醒/命令分离** (+0.0066): 关注点分离

**ELM 集成**是突破性的优化，提供了总提升的 50%。**唤醒/命令分离**恢复了 ELM 损失的性能，证明了架构设计的重要性。

**条件阈值方法经过测试被拒绝**，因为精确率差 (0.200) 且错误拒绝了合法命令。

当前最佳配置达到 **CER=0.1438, RR=0.9304, PR=0.9150, Score=0.8933**。

## Phase 1：共享 AED 权重（已采用）

唤醒与命令通道原本各持一份完整 FireRedASR2-AED。改为共用一份，唤醒侧用
`temporary_beam_size(1)` + `temporary_elm_weight(0.0)` 临时覆盖。

- **显存 7233 / 7628 MiB → 4818 MiB**，省下约一份 AED 权重
- datasetA 1838 条 **全字段逐位一致**，Score 0.8933 不变
- 解决一个悬案：改造前唤醒侧 ASR 配置相同却有 33/41 条转写不同，确认是两份
  模型同时驻留导致的数值/内核选择抖动，共享后归零。此前的"唤醒/命令 ASR
  分离"只是配置上隔离，数值上一直串扰

移植时踩到一个坑：`infer.py` 里原本就有一个同名的 `@property
temporary_beam_size`（死代码，返回工厂函数且不修改 nbest），定义在类体更靠
后的位置，把新方法遮蔽了，导致 `nbest > beam_size` 时 `torch.topk` 越界。已删除。

## Phase 2：ELM 后处理化（已采用）

**问题**：ELM 融入主解码会扭曲 `sequences_scores`，把 `raw_confidence` 从
~0.88 压到 ~0.60。切换规则读这个置信度，其 0.70 / 0.57 切点从未在该量程上
标定过——datasetX 上低置信分支恒真，规则退化成"恒切"。本文第 4 节记的 ELM
收益，在 datasetX 上实际全部来自这次退化带来的路由意外，而非转写质量。

**改法**：ELM 与 N-best 一律移到路由之后，只对选中通道跑一次；所有承载决策
的转写用 `temporary_elm_weight(0.0)` 解码。

顺带修掉一个隐性失效：N-best 原本只作用在 raw 命令上，切到分离通道的 56%
样本上它的重排结果被整个丢弃。

**必须配套重扫阈值**。沿用旧切点直接掉 0.0027；在恢复后的量程上重扫得到
0.88 / 0.76 / -0.03，三个参数都落在宽盆地内部。

| | CER | Score |
|---|---|---|
| 基线 | 0.1438 | 0.8933 |
| Phase 2 旧阈值 | 0.1492 | 0.8906 |
| Phase 2 重扫后 | 0.1430 | **0.8937** |

**+0.0004 在统计上不显著**（bootstrap 95% 区间 [-0.0020, +0.0029]，14 条更好
15 条更差），且阈值是样本内选的。分数上是平局；收益是结构性的：置信度污染
与失效的 N-best 通路都被消除，datasetX 上那种"规则退化成恒真"的病理不再可能
发生。

## Phase 3：单人 raw-only 路由（已测试，未采用）

移植对方的 12 维波形 logistic 路由器，判定命令音频为单人时抑制两路分离候选。

bundle 迁移本身成功：触发率 336/1838 = **18.3%**，与对方完全一致，说明模型
在我们的分离器输出上没有失配。

| | 值 | vs Phase 2 |
|---|---|---|
| PR | 0.9157 | +0.0007 |
| RR | 0.9283 | **-0.0021** |
| CER | 0.1423 | -0.0007 |
| Score | 0.8930 | **-0.0007** |

**否决理由**：`force_raw_only` 把两路分离置空 → `command_source_empty` 翻转
→ 改变 `*_sep` 门控特征（FusionGate 在有空通道时会把 `cos(anchor, raw_cmd)`
加进候选取最大）。57 条 sv_score 变化、122 条 cse 变化全部落在触发样本上，
两条判决翻转，其中一条负样本由拒变接受，吃掉了 CER 的收益。

关键在于**修不好**：把 Phase 3 的文本按 Phase 2 的门控判决重算得 0.8936，
仍低于 0.8937。路由器在我们链路上的文本贡献是 -0.0001。它在对方那里有效，
是因为对方基线是 conditional beam-1 且无拼音锚点；我们的拼音锚点加上重标定
后的切换规则已经挡住了它针对的那类失败。

保留为标签 `phase3-single-speaker-router`，主线不携带。

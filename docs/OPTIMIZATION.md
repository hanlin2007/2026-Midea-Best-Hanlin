# 优化历程（OPTIMIZATION）

本文档记录系统从基线到现役形态的完整优化实验：**每项优化解决了什么
问题、方案是什么、数字变化多少、代价是什么**，以及被否决的方案为什么
不行。读它的意义不在于记住数字，而在于学习"这类问题应该怎么实验、
怎么下结论"——每个结论都标注了证据强度。

源码对应：`docs/ALGORITHM.md` 的各节；本文按时间顺序组织。

## 性能演进总览

| 配置 | CER | RR | PR | Score | 提升 |
|------|-----|----|----|-------|------|
| 基线（融合门控 + 音色规则，beam=1） | 0.1945 | 0.9304 | 0.9150 | 0.8679 | - |
| + 拼音音素匹配 | 0.1831 | 0.9283 | 0.9164 | 0.8726 | +0.0047 |
| + N-best 重排序 | 0.1822 | 0.9304 | 0.9142 | 0.8741 | +0.0015 |

与延迟解码：分数持平，收益是结构性的（显存、时延、消除病理路径）。

## 1. 拼音音素匹配（+0.0047）

**问题**：ASR 最高频的错误是同音字。参考文本"你好科慕"，ASR 输出
"你好科目"——读音完全一样，字不同。字符级编辑距离罚 1 个字，但在
"哪一路分离通道念了唤醒词"这个判断里，读音一致已是足够强的证据。

**方案**：文本转拼音音节（pypinyin TONE3 去声调），在语音空间算编辑
距离，相似度 = 负距离。

**为什么有效**：同音字映射到相同拼音 → 距离 0；语音相似但不同的词 →
小距离；完全不同的词 → 大距离。与实际语义相似度有更好的相关性。

**代价**：平局处理——两路拼音一样像时回退原始唤醒音频（保守方向）；
只帮助语音错误，不帮助语义错误。

## 2. 唤醒词别名表（间接收益）

**问题**：同一唤醒词有多种合法表示：英文 "hi colmo"（拼音化 hicolmo）
与中文"嗨科慕"（haikemu），ASR 可能输出任一变体。

**方案**：双向别名表，参考文本展开成所有已知变体，逐变体算相似度取
最高分。

**为什么有效**：覆盖唤醒词的 ASR 变体；双向（中英两个方向）；可扩展。
**代价**：需要人工维护别名表；别名太多可能误匹配——保持克制。

## 3. N-best 重排序（+0.0015）

**问题**：beam=1 只返回概率最高的假设，可能错过"概率接近但字更对"
的候选。

**方案**：beam=3 解码取 N-best，做保守 MBR（最小贝叶斯风险）重排序：
选"与其他候选置信度加权差异最小"的假设，且置信度增益 ≥ 0.03、风险
下降 ≥ 0.05 双闸齐过才允许换人。

**为什么有效**：探索更多假设空间；MBR 选期望误差最小的候选；保守
双闸防止有害切换。**代价**：beam=3 慢约 3 倍；只作用于 1.3% 的样本
（大多数样本 top-1 已经很好）。

## 4. ELM 外部语言模型（+0.0126，最大单项）

**问题**：ASR 针对通用语音优化，偏好常见短语而非领域术语（设备名、
模式名），不知道"调到"比"掉到"更像指令。

**方案**：解码时融合外部语言模型分数：
`final = asr_score + 0.15 × elm_score`，使 ASR 偏向领域词汇。

**为什么有效**：纠正同音字错误；改善技术术语识别。
**代价**：RR 下降（ELM 让 ASR 对假阳性也更自信）；需要预训练 ELM。

## 5. 唤醒/命令通道分离解码配置（+0.0066）

**问题**：唤醒通道要"稳"（锚点选择需要确定性），命令通道要"准"
（需要探索性解码）——同一套解码配置无法兼得。

**方案**：唤醒侧 beam=1 + 无 ELM（稳定锚点），命令侧 beam=3 + ELM
（探索 + 领域偏向）。

**为什么有效**：关注点分离防止互相干扰；恢复了 ELM 造成的 RR 损失。
**代价**（后来被 Phase 1 消除）：当时驻留两份 AED 权重，显存 ~7.4 GB。

## 6. Phase 1：共享 AED 权重（结构性，分数不变）

唤醒与命令通道原本各持一份完整 FireRedASR2-AED。改为**共用一份**，
唤醒侧用 `temporary_beam_size(1)` + `temporary_elm_weight(0.0)` 临时
覆盖。

- **显存 7233/7628 MiB → 4818 MiB**（省下约一份 AED 权重）；
- 1838 条样本全字段逐位一致，Score 不变；
- 顺带解决一个悬案：改造前唤醒侧配置相同却有 33/41 条转写不同，
  确认是两份模型同时驻留导致的数值/内核选择抖动，共享后归零。
  此前的"唤醒/命令分离"只是配置隔离，数值上一直串扰。

**教训**：两个相同模型实例同时在显存里，不等于确定性推理。

## 7. Phase 2：ELM 后处理化 + 阈值重扫（+0.0004，结构性收益为主）

**问题**：ELM 融入主解码会扭曲 `sequences_scores`，把 `raw_confidence`
从 ~0.88 压到 ~0.60。音色切换规则读这个置信度，其切点从未在该量程上
标定过——低置信分支恒真，规则退化成"恒切"。第 4 节记的 ELM 收益，
部分实际来自这次退化带来的路由意外，而非转写质量。

**改法**：ELM 与 N-best 一律移到路由之后，只对选中通道跑一次；所有
承载决策的转写用 `temporary_elm_weight(0.0)` 解码。顺带修掉一个隐性
失效：N-best 原本只作用在 raw 命令上，切到分离通道的 56% 样本上它的
重排结果被整个丢弃。

**必须配套重扫阈值**：沿用旧切点直接掉 0.0027；在恢复后的量程上重扫
得到 0.88 / 0.76 / −0.03，三个参数都落在宽盆地内部
（c_hi [0.82, 0.92]，c_lo [0.60, 0.82]，tau [−0.05, −0.02]）。

| | CER | Score |
|---|---|---|
| Phase 2 前 | 0.1438 | 0.8933 |
| Phase 2 旧阈值 | 0.1492 | 0.8906 |
| Phase 2 重扫后 | 0.1430 | **0.8937** |

+0.0004 在统计上不显著（bootstrap 95% 区间 [−0.0020, +0.0029]），
分数上是平局；**收益是结构性的**：置信度污染与失效的 N-best 通路都
被消除，"规则退化成恒真"的病理不再可能发生。

**教训**：任何读置信度的规则，都与产生该置信度的解码配置耦合；
改编码配置必须重标定，且要在宽盆地中央选值，不选悬崖边。

## 8. 声学单双人路由 + 延迟解码（现役，结构性）

**方案**：20 维通道交换不变波形特征 + 线性 logistic 判"唤醒/指令各
是否单人"。双单人走独立短路（微调声纹 raw 余弦 ≥ 0.29 判同人）；
单人指令只解码原始指令；双人指令恒切分离通道、ft 余弦选路后只解码
选中一路（首选为空才补另一路），原始指令不解码。

**收益**：路由决策不再依赖任何 ASR 文本（消除"ASR 文本反向影响声纹
门控"的病理边）；指令 ASR 省一半以上；双单人样本省掉整套门控。
分类器触发率与上游参考实现完全一致（336/1838 = 18.3%），说明模型在
我们的分离器输出上没有失配。

## 被否决的方案（同样重要）

### 条件阈值（精确率 0.200，否决）

用路由/置信度/N-best/关键词/内容长度等多个信号调整接受门槛。实测拒
15 条样本：12 条真阳性被误拒、3 条假阳性被正确拒绝。**失败原因**：
合法命令的特征太多样，低置信度不等于假阳性，关键词分数不可靠
（许多有效命令 0 命中）——弱信号组合不成强判据。

### Phase 3：把单人路由做成"文本级"裁决（−0.0007，否决）

曾尝试用单人分类器抑制分离候选、只留 raw 转写。问题：`force_raw_only`
把两路分离置空 → `command_source_empty` 翻转 → 改变门控的 `*_sep`
特征（空通道时门控会把 raw 纳入候选取最大）——57 条门控分变化、
两条判决翻转，其中一条负样本由拒变接受，吃掉全部收益。且**修不好**：
按旧门控判决重算仍低于基线。它在上游有效，是因为上游基线没有拼音
锚点与重标定的路由；我们已经挡住了它针对的那类失败。

教训：单人路由只能用于"解码哪条音频"的路由，不能反向改门控输入。
现役实现正是这样做的。

### 其他未采用项

| 方案 | 否决原因 |
|---|---|
| conditional beam3 | −0.0029 CER 换 44.6% 时延；按 Score 计是亏 |
| 扩展门控特征 / lightgbm | 与现 6 维 bundle 打平，不值得加复杂度 |
| 批量 ELM (batch=16) | 最终提交需 batch=1 求确定性，对分数无贡献 |

## 反复出现的结构问题

`command_source_empty → *_sep` 这条"ASR 文本反向影响声纹门控"的边，
在合并过程中三次造成麻烦（ELM 换配置、恒切实验、单人路由）。语义上
它不该存在——现役系统用声学路由绕开了它；彻底切断需要重训融合
bundle，属于门控改造的范围。

## 关键洞察

**什么有效**
1. 语音相似度 > 字符相似度（用于唤醒词匹配）；
2. 领域语言模型是最大单项收益；
3. 关注点分离（唤醒求稳 vs 命令求准）防止干扰；
4. 保守双闸防止有害变化；
5. 便宜特征（波形统计）先行，短路贵流程（ASR/声纹）。

**什么无效**
1. 基于弱信号的条件阈值；
2. 拒绝合法命令的激进过滤；
3. 单信号决策（需要多个强信号）。

**性能瓶颈**（后续杠杆，按大小排序）
1. **门控占 CER 的 54%**：116 条正样本被拒、每条错满，共 740 字，
   是单一最大失分源；
2. **通道选择的 oracle 上界 +0.0088**：ft 余弦硬选一路，选错空间比
   "切不切"大三倍；
3. **动态阈值**：推导正确但实测收益为 0——门控在边界区的正负比
   够不着需求，依赖第 1 项先把边界判别力提上去。
